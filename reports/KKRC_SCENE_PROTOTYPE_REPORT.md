## 1. ما الذي بُني

(المكتبة منسوخة في `vendor/`)، وبلا أي ربط بمنطق اللعبة أو Mobile Controller.

## 2. البنية التقنية (الفصل المطلوب)

| الطبقة | الملف |
|---|---|
| **metadata (مصدر الحقيقة)** | `src/track_definition.js` — رياضيات صرفة، صفر اعتماد على Three.js |
| **geometry** | `src/geometry.js` |
| **materials** | `src/materials.js` |
| **props** | `src/props.js` |
| بيئة/إضاءة | `src/environment.js` |
| كاميرات | `src/cameras.js` |
| تجميع فقط | `src/main.js` + `index.html` |
| **الناتج القابل للنقل** | `metadata/kkrc_track_metadata.json` (يولَّد بـ `npm run export-metadata`) |

### محتوى `kkrc_track_metadata.json`

- `centerline`: حلقة مغلقة، 256 عينة `[x,0,z]` بالمتر
- `lane_boundaries`: حدود داخلية/خارجية للمضمارين + إزاحات مراكز الحارات الثماني
- `obstacle_anchors`: 12 مرساة موزعة على الـ centerline (موضع + اتجاه + s)
- `start_points`: 8 بوابات بداية عند s=300 (موضع واتجاه لكل حارة)
- `finish_line`: نقطتا الطرفين + الاتجاه عند s=380
- `camera_anchors`: مواضع/أهداف/fov الكاميرات الأربع
- نظام الإحداثيات والوحدات موثقان داخل الملف نفسه

## 5. القيود المعروفة

1. الأبعاد تقريبية مأخوذة بصرياً من الصور الجوية، ليست مساحية (survey). تغييرها لاحقاً = تعديل ثوابت `TRACK` ثم إعادة توليد الـ metadata.
2. المدرج والمباني كتل مبسطة low-poly تكفي للقطات المتوسطة والبعيدة؛ لقطات قريبة جداً ستحتاج تفصيلاً إضافياً.
3. `obstacle_anchors` مواضع منطقية فقط — لا تُرسم في المشهد (مقصود).
4. لا يوجد LOD — غير مطلوب عند هذه الميزانية (~43k مثلث).
