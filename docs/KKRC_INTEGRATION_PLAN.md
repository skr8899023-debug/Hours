# خطة دمج مشهد ميدان الملك خالد في مشروع اللعبة الرئيسي

**مصدر الدمج:** `prototype/king-khalid-racecourse/`
**الحالة:** `SCENE PROTOTYPE READY FOR INTEGRATION`

> ملاحظة مهمة: هذا المستودع لا يحتوي حالياً على مشروع اللعبة الرئيسي
> (كان فارغاً قبل هذا الفرع). الأقسام التي تشير إلى "ملفات المشروع الرئيسي"
> مكتوبة كقالب يُملأ بالمسارات الفعلية فور توفر المشروع الرئيسي في المستودع
> أو تحديد موقعه.

---

## 1. ما الذي سيُنقل

| الأصل | النوع | الاعتماديات |
|---|---|---|
| `src/track_definition.js` | مصدر الحقيقة لهندسة المضمار والمراسي | **صفر** — رياضيات صرفة، ينقل كما هو لأي محرك JS |
| `metadata/kkrc_track_metadata.json` | بيانات جاهزة للاستهلاك (centerline، حارات، بوابات، خط نهاية، عوائق، كاميرات) | صفر — JSON قياسي، صالح حتى لمحركات غير JS (Unity/Godot/Unreal) |
| `src/geometry.js` | بُناة أسطح المضمار والسياج والممرات | Three.js + `track_definition.js` |
| `src/materials.js` | مكتبة الخامات + مولد نسيج الضوضاء | Three.js فقط |
| `src/props.js` | النخيل/المدرج/المعالم/البيئة البعيدة (instanced) | Three.js + `geometry.js` + `track_definition.js` |
| `src/environment.js` | الإضاءة النهارية والسماء والضباب | Three.js فقط |
| `src/cameras.js` | مراسي الكاميرات الأربع + التبديل | Three.js + OrbitControls |
| `tools/export_metadata.mjs` | إعادة توليد الـ metadata عند أي تعديل | Node فقط |

**ما لن يُنقل:** `index.html`، `main.js`، `vendor/` — هذه أغلفة تشغيل مستقل؛
المشروع الرئيسي له نقطة دخوله ونسخته من المكتبات.

## 2. كيف سيُنقل

1. **إن كان المشروع الرئيسي Three.js/JS:** تُنسخ وحدات `src/` إلى
   `<main>/scenes/kkrc/` كما هي (كلها ES modules نقية تستقبل الاعتماديات
   بالاستيراد)، ويستدعي مشهد اللعبة `buildTrackGroup(materials)` و
   `buildProps(materials)` و`setupEnvironment(scene)` بدل محتوى `main.js`.
2. **إن كان المشروع بمحرك آخر:** يُستهلك `kkrc_track_metadata.json` مباشرة
   لبناء spline المضمار والحارات والمراسي، وتُعاد نمذجة الأسطح بأدوات المحرك
   بنفس الأبعاد — الـ JSON يحمل كل شيء بالمتر وبنظام إحداثيات موثق داخله.
3. منطق السباق (خيول/تصادم/تقدم) يقرأ من الـ metadata فقط:
   - مسار الحركة: `centerline` + `lane_center_offsets`
   - البداية/النهاية: `start_points.gates` و`finish_line`
   - العوائق المستقبلية: `obstacle_anchors`
   - كاميرات البث: `camera_anchors`
4. Mobile Controller يُربط **بعد** ثبات المشهد، عبر تحريك كيان اللاعب على
   `centerline` بإحداثي (s, o) — الدوال `pointAt/offsetPointAt` جاهزة لذلك.

## 3. الملفات المتأثرة في المشروع الرئيسي (قالب يُملأ عند توفر المشروع)

| الملف/المسار المتوقع | التغيير |
|---|---|
| `<main>/scenes/` أو ما يعادله | إضافة مجلد `kkrc/` بالوحدات المنقولة |
| ملف تعريف/تسجيل المشاهد (scene registry) | تسجيل مشهد KKRC |
| إعدادات المسارات/الحلبات (track config) | الإشارة إلى `kkrc_track_metadata.json` |
| نظام الكاميرات | استهلاك `camera_anchors` بدل قيم مكتوبة يدوياً |
| نظام السباق/الحركة | القراءة من `centerline` و`start_points` و`finish_line` |
| `package.json` الرئيسي | لا جديد إن كان Three.js موجوداً؛ وإلا إضافة `three` |

## 4. المخاطر

| الخطر | الأثر | التخفيف |
|---|---|---|
| اختلاف نظام إحداثيات المشروع الرئيسي (محور up، اليد، الوحدة) | انقلاب/تحجيم خاطئ للمسار | نظام الإحداثيات موثق داخل الـ JSON؛ تُطبق مصفوفة تحويل واحدة عند الاستيراد وتُختبر بنقطتي البداية والنهاية |
| اختلاف نسخة Three.js في المشروع الرئيسي | كسر API (خاصة `outputColorSpace`/الإضاءة بين r150–r160) | الوحدات مكتوبة على r160؛ عند الدمج تثبّت النسخة أو تُراجع نقاط الـ API الثلاث (colorSpace, tone mapping, lights) |
| تعديل أبعاد المضمار لاحقاً دون إعادة توليد الـ metadata | تباعد بين المرئي والمنطقي | المصدر واحد (`track_definition.js`)؛ تُضاف خطوة CI/برمجية تعيد `export-metadata` عند أي تغيير |
| ميزانية أداء الموبايل أضيق من المقاس | هبوط FPS | المقاس ≤100 draw calls/~43k مثلث؛ هوامش خفض جاهزة (تقليل عدد النخيل/الشجيرات عبر ثوابت واحدة في `props.js`) |
| الظلال على أجهزة ضعيفة | كلفة GPU | تعطيل `shadowMap` أو خفض دقته 1024 — سطر واحد في إعداد الـ renderer |
| دقة الأبعاد ليست مساحية | فروق عن الميدان الحقيقي | إن توفرت أبعاد رسمية تُحدّث ثوابت `TRACK` ويُعاد التوليد — كل شيء يشتق تلقائياً |

## 5. خطوات الدمج

1. تحديد/إحضار المشروع الرئيسي وتثبيت مساراته الفعلية في الجدول أعلاه.
2. نسخ `src/track_definition.js` و`metadata/kkrc_track_metadata.json` أولاً — هذه تكفي لبدء ربط منطق السباق حتى قبل نقل المرئيات.
3. نسخ وحدات المرئيات (`geometry/materials/props/environment/cameras`) إلى مجلد المشهد في المشروع الرئيسي.
4. إنشاء ملف تجميع للمشهد داخل المشروع الرئيسي (مكافئ `main.js` بدون HUD المستقل)، وربطه بحلقة التحديث ونظام الكاميرات هناك.
5. اختبار بصري مقارنة باللقطات المرجعية في `reports/screenshots/` (نفس مراسي الكاميرات الأربع = مقارنة مباشرة).
6. ربط منطق السباق بالـ metadata (بوابات، خط نهاية، centerline) واختبار لفة كاملة لكيان اختباري.
7. ربط Mobile Controller (آخر خطوة، بعد ثبات كل ما سبق).
8. قياس الأداء على جهاز موبايل مستهدف؛ عند الحاجة: خفض الظلال ثم أعداد الـ instances.

## 6. معيار القبول

- المشهد داخل المشروع الرئيسي يطابق اللقطات الأربع المرجعية.
- لفة كاملة لكيان اختباري على `centerline` دون خروج عن الحارات.
- FPS مستقر على الجهاز المستهدف بالميزانية الحالية أو أقل.
